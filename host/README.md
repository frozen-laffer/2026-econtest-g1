### 触摸屏版（`lsa_touch.py`）说明

面向 6 英寸以上触摸屏，**不需要键盘、不需要输入任何字符**：

* 启动自动连接 `192.168.57.200:5000`，连不上只是顶栏显示「未连接」，点「连接」重试即可
* 全部操作都是大按钮（最小触摸高度 56 px）：`采集` / `周期 1|3` / `档位 自动|0|1|2|3` / `三路交替 开|关` / `去 u3 开|关` / `保存` / `自检` / `退出`
* 版式固定不滚动：顶栏 → 左波形右频谱 → 五格大字号读数（Upp / Urms / 基频 f1 / 基波幅值 / THD）→ 两行控制条
* **两个坐标系都自动量程**：波形按**交流分量**取半量程（直流偏置不占视窗，偏置值显示在标题 `Udc=` 里），量程吸附到 1/1.5/2/2.5/3/5/7.5×10ᵏ，读数稳定不跳；频谱纵轴 0 到峰值×1.15 同样吸附，横轴 0~max(600 kHz, 1.3·f1)；无信号时波形固定 ±0.5 mV、频谱固定 0~1 mV，不会把噪声放大成"波浪"
* 默认全屏（`--no-fullscreen` 可窗口化调试），`退出` 需二次确认
* 档位默认 **0（10.625 MSPS 三路 / 3.542 MSPS 单路）**；「自动」只在四个档位里挑带外能量最小的，且会先排除 Nyquist < 700 kHz 的档位，避免 u3 混叠
* 1024×600 是最小可用分辨率（实测该尺寸下所有控件完整可见）；1280×800 更宽松

**网络**：树莓派网口必须与板子同网段，且**不能和树莓派自己的 WiFi 网段重叠**（重叠会导致回包从错误网卡发出、ping 不通）。用 NetworkManager 建一个持久化配置：

## 3. 协议速查

### 命令帧（主机 → 板卡，16 字节，小端）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u32 | magic `'LSCO'` = `0x4F43534C` |
| 4 | u8 | cmd：1=PING 2=CAPTURE 3=STATUS 4=ABORT 5=SET_AFE 6=SELFTEST |
| 5 | u8 | CAPTURE：档位 gear 0..3 / SET_AFE：通道 0..2 |
| 6 | u8 | CAPTURE：1=三路交替，0=单路 / SET_AFE：1=AC 耦合 |
| 7 | u8 | CAPTURE：单路时的通道 / SET_AFE：1=20× 衰减 |
| 8 | u8 | SET_AFE：1=20× 增益 |
| 9 | u8 | 保留 |
| 10 | u16 | 本次采集总点数 |
| 12 | u32 | 事务号 tok（回显，用于配对） |

### 数据/应答头（板卡 → 主机，32 字节，小端）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u32 | magic `'LSDA'` = `0x4144534C` |
| 4 | u8 | ver = 1 |
| 5 | u8 | type：0=ACK 1=DATA 2=ERR |
| 6 | u8 | gear |
| 7 | u8 | mode：0=单路 1=三路交替 |
| 8 | u32 | fs_hz（**实际采样率**，不是标称值） |
| 12 | u32 | n_total |
| 16 | u32 | n_this（本次报文携带的点数） |
| 20 | u32 | gain_milli（总增益 ×1000，如 3925） |
| 24 | u32 | tok |
| 28 | u16 | flags（bit0 = 三路交替自检通过） |
| 30 | u16 | CRC-16/CCITT（对前 30 字节） |

DATA 报文 = 32 B 头 + `n_this` 个 **int16 原始差分码**（交织顺序，12 位补码，满量程 ±2047）。
**CAPTURE 成功时不回 ACK，直接回 DATA**；失败回 type=ERR。

## 4. 采样档位

| gear | 单路 fs | 三路交替 fs | N（三路） | Δf = fs/N | 采集时长 |
|---|---|---|---|---|---|
| 0 | **3.542 MSPS** | **10.625 MSPS** | 24576 | **432 Hz** | 3.47 ms |
| 1 | 2.656 MSPS | 7.969 MSPS | 24576 | 324 Hz | 3.47 ms |
| 2 | 2.125 MSPS | 6.375 MSPS | 24576 | 259 Hz | 3.47 ms |
| 3 | 1.771 MSPS | 5.313 MSPS | 24576 | 216 Hz | 3.47 ms |

赛题要求频率分辨率 **500 Hz** —— 四档全部满足（144~288 Hz，余量 ≥1.7 倍）。

三路交替把 ADC1/ADC2/ADC5 分别用 TIM8 的 UPDATE / CC1 / OC2REF 触发，相位差 ⅓ 个
采样周期，因此等效采样率是单路的 3 倍。交错带来的失配杂散落在 `fs/3 ≈ 2.36 MHz`
和 `fin ± fs/3`，**全部在 600 kHz 分析带之外**，对本题无影响。

## 5. 赛题操作流程

### 题 1 —— 键控显示 1 或 3 个完整周期

1. 接信号到任一路输入，点「采集」（或空格）。
2. 界面左侧自动按基频 f1 截取 **1 个 / 3 个完整周期**，用下拉框或键盘 `1` / `3` 切换。
3. 读数条给出 Upp、Urms、f1。

### 题 2 —— 200 kHz、500 kHz 以内

直接采集即可（三路交替档 0 时 fs=7.083 MSPS，500 kHz 有 7 倍过采样）。
频谱默认画到 600 kHz。

### 题 3 —— 抑制 f3（≥1 MHz）后测 u2

1. 勾选「**去 u3**」（数字低通，截止 700 kHz）。
2. 采集：固件负责搬到 7.083 MSPS（此时 1 MHz 的 f3 远低于 Nyquist，**不混叠**），
   上位机再用 257 阶 Kaiser 低通（fc=700 kHz，600 kHz 内完全平直，1 MHz 处 −122 dB）把它滤掉。
3. 滤波后丢掉两端各 128 点（避免边界瞬态抬高 Upp），再测 Upp/Urms/f1/各分量。
4. 频谱图上只保留 700 kHz 以内的分量。

验证（合成信号，u2=100 kHz/200 mVpp，u3=3.1 MHz/600 mVpp）：

```
滤波前: Upp = 800.19 mV   f1 = 3100000.0 Hz
滤波后: Upp = 200.001 mV   Urms = 70.698 mV   f1 = 100000.0 Hz   基波 = 100.000 mV
```

f3 残留 < 1 µV，Upp 误差 1 µV 量级，远优于 5 mV 的判据。

## 6. 精度自检

### 6.1 一键离线自检（不接硬件）

```bash
python3 selftest_dsp.py        # 加 -v 打印每个用例
```

它把「真值 → 12 bit 差分量化 → DSP」整条链路跑一遍，覆盖三个赛题场景。
**2026-11-11 实测结果**：

| 场景 | 条件 | 最坏误差 | 判据 | 结论 |
|---|---|---|---|---|
| 题1/题2 | fs=2.361 MSPS, N=8192, Δf=288 Hz, 增益 3.925；f1 = 10k…499k，Upp = 50/100/250 mV，含 2/3 次谐波 | Upp **0.348 mV**、Urms **0.013 mV**、f1 **0.0 Hz** | ≤5 mV / ≤1 kHz | **PASS**（24 个用例 0 超差） |
| 题3 | fs=7.083 MSPS, N=24576，u2=100 kHz/200 mVpp + 300 kHz/50 mVpp，u3=200 mVpp @ f3 | 分量误差 **≤0.014 mV**；u3 残留 **<0.001 mV** | ≤5 mV | **PASS**（f3 = 1.0/1.2/1.5/2.0/3.0 MHz） |
| 三路交替 | 给 ADC5 注入实测的 +737.8 mV 偏置 + 0.368 mV(rms) 噪声 | 修正前 Upp 谎报 **938.94 mV**（4.7 倍）；修正后 **202.04 mV**，误差 **+2.04 mV** | ≤5 mV | **PASS** |
| 毛刺抑制 | 200 mVpp 信号上打 1 / 3 / 8 个 **+500 mV 单点尖峰** | 原始 Upp 655~700 mV（谎报 3.3~3.5 倍）；抗毛刺后 **200.000 mV**，误差 **−0.001 mV** | ≤5 mV | **PASS** |
| 非正弦波形 | 方波 / 三角波 / 半波整流，f1 = 10k/50k/100k，Upp = 250 mV | 方波 **+0.001 mV**、三角波 **−0.177 mV**、半波 **0.000 mV** | ≤5 mV | **PASS** |

> 三路交替那 2.04 mV 的残余误差全部来自 ADC5 的噪声，已经吃掉 40% 的误差预算。
> 所以**题1/题2 建议用单路 ADC1**（底噪 0.00 mV），三路交替只在题3 需要更高 Nyquist 时用。

#### 非正弦波形为什么必须用「基波解析换算」

带限重建后直接取 `max−min` 会踩 Gibbs 过冲：**方波无论加到多少次谐波，Upp 都固定高估 +17.9%**
（K=1 时 +27.3%，K=25 时 +17.9%），三角波则低估（K=9 时 −4%，K=1 时 −18.9%）。
250 mVpp 的方波会被读成 295~303 mV，**超差 45~53 mV**。

所以 `lsa_dsp.measure()` 会先判型，再用基波幅度解析换算：

| 波形 | 谐波特征（a₃/a₁, a₅/a₁, a₇/a₁） | 换算 |
|---|---|---|
| 正弦 | ≈0, ≈0, ≈0 | `Upp = 2·a₁` |
| 方波 | 1/3, 1/5, 1/7 | `Upp = (π/2)·a₁ = 1.5708·a₁`，`Urms = Upp/2` |
| 三角波 | 1/9, 1/25, 1/49 | `Upp = (π²/4)·a₁ = 2.4674·a₁`，`Urms = Upp/(2√3)` |
| 半波整流 | a₂/a₁ ≈ 0.42，a₃ ≈ 0 | `Upp = 2·a₁`，`Urms = Upp/4` |

多音信号（题3 的 u₂=100k+300k）的 5/7 次谐波对不上方波/三角波的 1/k、1/k² 规律，**不会被误判**
（自检里专门加了两个双音用例验证）。

> **边界**：f₁ > 167 kHz 时 3 次谐波已超出经校准的 520 kHz 带，无法判型，按正弦假设处理
> ——此时若输入是方波会高估约 18%。赛题该频段（题2 的 200 kHz 档）输入为正弦，可接受。

### 6.2 `lsa_cli.py demo`

| 项目 | 真值 | 实测 | 误差 |
|---|---|---|---|
| f1（137 123.4 Hz，非整 bin） | 137123.4 Hz | 137123.40 Hz | 0.00 Hz |
| 基波幅度 | 100.000 mV | 100.000 mV | <0.001 % |
| Upp | 200.000 mV | 200.000 mV | <0.001 % |
| Urms | 70.711 mV | 70.711 mV | <0.001 % |

幅度精度靠三件事保证：Blackman-Harris 窗（旁瓣 −92 dB）+ 相干增益补偿
（`amp = 2|X|/Σw`）+ **4 倍补零**（不打补零的话粗网格采不到窄主瓣峰顶，会低 0.25%）。

### 6.3 树莓派上的实测耗时（2 s 预算）

`measure()` 用 `pad=4`；一次刷新只做 **一次 FFT**，`components()` 与
`harmonic_amplitudes()` 通过 `spec=` 复用这份频谱。

| 场景 | 点数 | FFT 规模 | 耗时（树莓派 4） |
|---|---|---|---|
| 单路 ADC1 | 8192 | 32768 | **171 ms** |
| 三路交替 | 24576 | 131072 | **306 ms** |
| 三路交替 + 去 u3（含 257 阶 FIR） | 24576 | 131072 | **338 ms** |

加上采集（≤10 ms）与 48 KB 传输（约 40 ms），题 3 最坏情况 **约 0.4 s**，
余量 5 倍。作为对比：`pad=32` 且不复用频谱时同样一帧要 **4.2 s**——会直接超时。

## 7. 校准

### 7.1 零输入基线（每通道直流偏置）

三路模拟前端各有直流偏置（本板实测 ADC5 约 **+737.8 mV**，ADC1/ADC2 约 0）。
三路交替时这些偏置被交织进同一串数据，会在 **fs/3**（2.361 MHz）造出假信号，
时域 Upp 直接虚报到 790 mV 以上。扣掉之后三路交替才能用于题 1/题 2。

**操作（全触摸，一次点按）**

1. 输入端**短路**（最好短路；空载也可以，偏置会略有差别），系统上电预热 1 分钟；
2. 「三路交替」开关拨到比赛时要用的状态；
3. 点「校准」→ 确认 → 板子采一帧零输入数据，把每路均值写进 `calib.json`；
4. 按钮变成「校准 ✓」，之后每次采集自动扣除。

命令行等价操作：`python3 lsa_cli.py calib`（先关掉图形界面，板子只有一个 TCP 连接）。

`calib.json` 结构（按增益档分开存，换档没有记录就不修正）：

```json
{
  "version": 1,
  "updated": "2026-11-11T14:30:00",
  "source": "shorted_or_floating",
  "gain_milli": 3925,
  "offsets_v": { "0@3925": 0.0000, "1@3925": 0.0000, "2@3925": 0.7378 }
}
```

实测效果（`selftest_dsp.py` 的「零输入基线标定」一组）：Upp 938.76 mV → **201.72 mV**
（真值 200.00 mV），三路残余偏置 +0.047 / +0.046 / +0.049 mV。
注意剩下的 **1.72 mV** 不是偏置而是 ADC5 的噪声（0.368 mV rms），标定消不掉——
所以题 1/题 2 仍建议用单路 ADC1（误差 0.35 mV），三路交替留给题 3。

### 7.2 增益校准

1. `gain_milli` 由固件按 `AFE_GetTotalGain()` 上报（名义值：×2 档 = 3925，×20 档 = 39520）。
2. 若与实测差 >0.5%，用 `lsa_cli.py cap` 采一组已知幅度信号，算出修正系数，
   在 `lsa_app.py` 里 `dsp.codes_to_volts(...)` 之后乘一个标定因子即可（或改
   `lsa_dsp.codes_to_volts` 的 `gain_milli` 实参）。
3. 直流失调：`measure()` 返回的 `udc` 即残余失调，正常应在 ±0.1 mV 以内（标定后）。

### 7.3 幅频补偿（`lsa_eq.py` / `eq.json`）

这块板子的模拟链路**不是平的**：250 mVpp 输入时，采到的 Upp 从 10 kHz 的
640 mV 一路掉到 500 kHz 的 **137 mV**（−13.4 dB）、550 kHz 的 90 mV。
不补偿的话，500 kHz 的 250 mVpp 只会读到 **54 mV**。

`lsa_eq.apply()` 在频域按实测表把 `1/|H(f)|` 乘回去（零相位，只改幅度），同一趟里还做两件事：

- **低端高通**：0→5 kHz 升余弦，压掉漂移 / 1/f / 直流残差（题1 最低成分 10 kHz，留够余量）；
- **高端收口**：从表的上限（550 kHz）起，用 `0.25·f` 的跨度把补偿量线性收回 1.0。
  这一步不能省：表只测到 550 kHz，而那里已经要补 **×7.2**，若继续"保持最后一点增益"，
  1 MHz 的 u3 会被放大 7 倍、宽带噪声同比放大，谱图和 Upp 全部虚高；
- 两端各裁 `TRIM_S = 0.45 ms` 的过渡带（不裁的话 100 kHz 会偏高约 1.2 mV）。

**现在用的是实测表，不是解析模型**。实测表长这样（`eq.json`）：

```json
{ "version": 1, "source": "table",
  "table": [[10000, 1.0012], [14000, 1.0000], ..., [550000, 0.1402]],
  "model": {"fn": 234700, "Q": 0.695} }
```

`model` 只是给 `summary()` / `boost_at()` 参考用的粗描述（单级二阶拟合 RMS 0.63 dB，
说明这条曲线已经不是干净的二阶），真正参与计算的是 `table`。

整体增益由 `config.json` 的 `in_scale` 负责：`in_scale = 标称幅度 / 低频平台 Upp`
（例如 250 / 639.25 = 0.3911），在补偿**之后**统一乘上去。

实测精度（AFG 给 250 mVpp，补偿开）：

| f | 采到 | 补偿后显示 | 误差 |
|---|---|---|---|
|100 kHz|591.8 mV（表内插）|**251.1 mV**|+1.1 mV|
|300 kHz|340.9 mV|**250.5 mV**|+0.5 mV|
|500 kHz|137.4 mV|**249.5 mV**|−0.5 mV|

用法：

- 触摸版顶栏「**补偿 开/关**」按钮，默认开；采集后状态栏显示 `补偿 +13.4 dB@500 kHz`；
- 命令行 `--no-eq` 关闭，`--eq <path>` 指定别的表。

**注意**：这只补偿幅度、不补偿相位。真正修好模拟板之后**必须重跑一次校准**（或关掉补偿），
否则会在高频过度提升。补偿也不会改善信噪比——500 kHz 提升 13.4 dB 的同时噪声同比例放大。

### 7.4 阶梯校准（21 点）

换板、换温度、改过模拟前端之后重新标定，有两条等效的路子：**触摸屏上引导式点 21 下**
（不需要电脑），或者**在 PC 上一条命令**（需要 AFG 接 USB）。

两者用的是同一套算法：21 个固定频点逐点停住采集 → 除以 ≤20 kHz 的低频平台归一化 →
建幅频表写 `eq.json`，`in_scale = 250 / 平台 Upp` 写 `config.json`，再拟一个单级二阶
`fc/Q` 只作参考。

频点（低端密、400 kHz 以后加密，那里斜率变化最快）：

```
10 14 20 28 40 56 80 110 150 200 250 300 350 400 440 470 500 520 550   (kHz)
```

#### 7.4.1 触摸屏引导式（推荐，现场用这个）

控制条最右「**阶梯校准**」→ 对话框逐点提示：

```
第 3 / 21 点：把信号源设为 20 kHz / 250 mVpp
[采一点]  [跳过]  [关闭]
──────────────────────●────────────────
已采 2 点 / 21    待采 20 kHz
已采 2 点  最近：10 kHz → 160.0 mV　14 kHz → 160.0 mV
```

每点：把信号源设到提示的频率（正弦、偏置 0 V、幅度 250 mVpp，**负载设 50 Ω 或高阻都行**）
→ 按「采一点」。21 点按完自动建表、写盘、界面立即生效。

- 频率设错会被挡住：读到的 `f1` 与提示频率差 **>3%** 时提示「频率不对…检查信号源」，
  这一点**不计入**，改好再按；
- 某点设不了就按「跳过」，至少采 **6 点**才能建表；
- 归一化基准取 ≤20 kHz 的平台，所以源上写 250 mVpp 还是 100 mVpp 都不影响形状，只影响信噪比。

离线回归（`_test_stepcalib.py`，用合成链路代替板子）：21 点全采到，表比值与合成模型的
最大偏差 **0.04%**，拟合 **fc = 234.0 kHz / Q = 0.694**（真值 234.0 / 0.694，RMS 0.003 dB），
`in_scale` 与理论值偏差 **0.000%** —— `PASS`。已在树莓派实机打开验收过（1024×600 全屏可放下）。

**真机实测（2026-11-15，源 250 mVpp，gear0 / N=16384）**：21 点 53 秒采完，低频平台
638.75 mVpp，拟合 **fc = 235.2 kHz / Q = 0.702**（RMS 0.629 dB），`in_scale = 0.3913878`。
补偿后**表内** 100/300/500 kHz 读 250.27 / 249.92 / 249.85 mV；**表外 20 个缝隙点**
最大误差 **0.66 mV**（130 kHz）、平均 +0.04 mV、标准差 0.33 mV —— 对 5 mV 预算余量 86.8%。
（19 点表时表外最大误差 1.41 mV；补上 325 / 375 kHz 两点后，300~400 kHz 那段从
−1.3 / −1.4 mV 压到 −0.3 mV 以内。）

#### 7.4.2 PC 侧一键（`cal_step.py`，AFG-2225 接 COM17）

```powershell
python cal_step.py                 # 采表 + 拟合 + 写 eq.json/config.json + 上传树莓派 + 复测修正
python cal_step.py --dry-run       # 只采表看数据，不写文件
```

它做四件事：

1. 杀掉树莓派上的触摸界面（板子只允许一条 TCP 连接），把 `cap_one.py` 传到树莓派；
2. 逐点设 AFG（**每点回读校验**，被静默丢弃会自动重写）→ 经树莓派采一帧 → 收 Upp；
   默认 21 个点、250 mVpp，全程约 50 秒；
3. 归一化成幅频表 + 拟合 fc/Q → 写 `eq.json` / `config.json` 并上传；
4. 在 100/300/500 kHz 再采一次「补偿后」的值，若均值偏离目标超过 0.2% 就自动修正
   `in_scale` 并重新上传（三点离散度 >2% 时**拒绝**修正——那是响应形状变了，不是整体比例错）。

#### 7.4.3 为什么不用扫频

原来的「扫频校准」要手动把信号源设成对数扫频、连录 70 s。两个问题：AFG 的 SCPI 扫频在这台
机器上不生效；更根本的是 **3.47 ms 的采集窗在连续扫频时会扫过好几个频点**，谱峰被抹平。
逐点停住再采，频率由人眼确认（或回读校验），精度高得多。

> 幅度估计用 `dsp.measure(..., force_wave="sine")`（谐波最小二乘，`Upp = 2·a1`），
> **不要用 `np.ptp`**：550 kHz 处信号只剩 ~35 mVpp（±1~2 码的噪声），ptp 会把极值算进去，
> 标定表被抬高 **2~7%**，补偿就欠了。离线验证（`_test_stepcalib.py`）：换用 measure 后
> 建表的 |H| 比值与合成模型最大偏差从 **6.78% 降到 0.06%**，拟合 fc 从 242.2 kHz 回到 234.1 kHz。

### 7.5 激励面板（自己出题，不用碰信号源面板）

主界面底部「激励」按钮打开 `SourcePanel`（`lsa_touch.py`）。现场老师不会调 AFG 面板，
这个对话框把"设频率/幅度"变成"填几个数"。

- **左边**：10 个赛题预置（点一下就把参数填进表单），或者 8 个输入框自己填
  —— 基频 kHz、1 次/2 次谐波的次数与相对幅度、总峰峰值 mV、干扰频率 MHz（0=无）与干扰 mV。
- **右边三列对照**，一眼分清误差来源：

  | 列 | 含义 |
  |---|---|
  | 预设（你要的） | 按输入框算出来的理论值 |
  | 回读（源里实际） | 信号源 `FREQ?`/`AMP?` 回读，以及**下发量化后**各分量的实际峰值（把整数缓冲按 511 档重新做最小二乘反算） |
  | 实测（板子） | 板子采回来、经幅频补偿 + `in_scale` + 谐波拟合后的值 |

  末尾给一句结论：基频差 ≤1 kHz 且 Upp 差 ≤5 mV 判「一致 ✓」，否则列出差在哪一项。

- **点数不再固定 4096**：`N = min(4096, floor(120e6 / f1))`，采样率 = `f1·N` ≤ 120 MSa/s，
  于是谐波天然是整数个周期，任何 f1 都能精确设定（10 kHz → 4096 点 @40.96 MSa/s，
  100 kHz → 1200 点 @120 MSa/s，234.4 kHz → 512 点）。要求 `N/k_max ≥ 8`（每周期至少 8 点）。
- **干扰频率必须是基频的整数倍**，否则整周期重放装不下，会直接报错而不是静默出错。
- 装载用 `lsa_src.Afg2225.load_arb()`，写序是
  `FUNC SIN` → `DATA:DAC VOLATILE` → `VOLT:UNIT VPP` → `FREQ` → `AMP` → `DCO` → **最后 `FUNC USER`**
  （反过来频率会被复位成 16.67 Hz）。

实机验证（题1-A 预置，29.2969 kHz / 250 mVpp）：预设 107.4+64.4 mV → 回读 107.2+64.3 mV
→ 实测 107.3+64.4 mV，`Upp 250.7 vs 250.0 mV（+0.71 mV）`、基频差 0.4 Hz。

## 9. 排障

| 现象 | 处理 |
|---|---|
| 连接失败 | `ping 192.168.57.200`；确认树莓派网口同网段；板子上电后 W5500 绿灯常亮 |
| 采集报 `错误码 4` | 固件 500 ms 内没等到三路 DMA 完成 → 跑 `selftest`，失败就关掉「三路交替」用单路 |
| f1 读成 0 或不稳 | 信号太小或档位不对；先 `auto` 自动选档 |
| 波形显示不满 1 个周期 | f1 估错，通常是谐波比基波强；把输入幅度降下来或用 `--gear` 指定档位 |
| Windows 控制台中文乱码 | `chcp 65001`，或用图形界面 |

## 10. 参数备份到板子 Flash（W25Q16）

树莓派重刷系统后 `eq.json / config.json / calib.json / excite.json` 会全丢，
所以板子上那颗 **W25Q16JVSSIQ（U5，2 MB，SPI1：PB3/PB4/PB5，CS=PB6）**
留了两个 4 KB 扇区专门存这四个文件的打包副本。

| 项 | 值 |
|---|---|
| A 槽 | `0x00100000` |
| B 槽 | `0x00101000` |
| 头 | 16 B：`'LSP1'` \| ver u16 \| len u32 \| seq u32 \| crc16 u16 \| rsv u16 |
| 轮换 | 每次保存写**序号小的那个槽**，另一个槽原样留着 → 掉电时至少一份完整 |
| 上限 | 8192 B（四个 json 加起来 ~4 KB，余量充足） |

**自动行为**（`lsa_touch.py`）：

* 阶梯校准写完 `eq.json/config.json` → 自动存一份到板子；
* 激励面板每次「装载」写完 `excite.json` → 自动存一份；
* 连上板子时如果本地**缺**这些文件（刚重刷系统）→ 自动从板子读回来并重新加载。

**手动**（`lsa_param.py`）：

```bash
python3 lsa_param.py info      # 板子里存了多少字节、序号多少
python3 lsa_param.py save      # 把本地四个文件打包存进板子
python3 lsa_param.py load      # 从板子读回来覆盖本地
python3 lsa_param.py clear     # 清空两个槽
```

协议上是三条命令（见 §3）：`PARAM_BEGIN(总长)` → `PARAM_CHUNK(偏移+1024 字节数据)×N`
→ `PARAM_COMMIT`；读回是 `PARAM_INFO`（返回长度/序号）与 `PARAM_LOAD(偏移, 长度)`。

## 11. 已知边界

* 只处理**单频基波 + 谐波**的周期信号，不处理调幅/调频。
* 基频下限按 1 kHz 设计（赛题最低 10 kHz，余量充足）。
* 板卡模拟前端若存在 32 MHz 自激（早期实测 1 V 量级），**会在 7.083 MSPS 下折叠到
  约 2.36 MHz**，落在分析带外，对本题无影响；但它会让 ADC 输入被大信号占据，动态范围
  变差，仍建议硬件上消除。
* 三路交替依赖 TIM8 的 CC1/OC2REF 触发链，若某路 DMA 不完成，固件自检会报错，
  上位机会自动降级到单路（采样率降为 1/3，仍满足 500 Hz 分辨率要求）。

## 11 板载掉电日志（W25Q16）

树莓派系统卡死/重刷后 `/var/log` 就读不出来了，所以运行日志实时推到 STM32 自己
的 Flash 上：`0x00104000` 起 8 个扇区（32 KB）环形覆盖，每条记录占一个 128 字节
槽位（`seq u32 | level u8 | len u8 | crc16 | 正文<=120B`），**不跨 256 字节页、掉电
写了半条会被 CRC 判掉**。板子收到每条日志时同时从调试串口（USART1, 115200）打
一遍：

```
[LOG] #12 L3 采集失败：ConnectionRefusedError
```

所以哪怕 Pi 彻底不启动，把板子接到 USB-TTL 上仍能看到最后一次报错。

命令行（在 Pi 上跑）：

```bash
python3 lsa_log.py info            # 多少条 / 用了几个扇区
python3 lsa_log.py dump            # 全导出，从旧到新
python3 lsa_log.py dump --from 120 # 只看序号 >= 120
python3 lsa_log.py tail            # 1 Hz 跟随
python3 lsa_log.py put ERR "XXX 挂了"
python3 lsa_log.py clear
python3 lsa_log.py watch /path/to/monitor.log   # 转发任意程序的日志文件
```

监测程序里直接调：

```python
import lsa_log
log = lsa_log.Logger(tag="monitor")   # 默认短连接：写完就关，不占用板子唯一连接
log.info("启动完成")
log.err("AFG 打开失败：%s" % e)
```

`Logger(persistent=True)` 才开长连接（给 `watch` 那种高频转发用）。板子只允许一条
TCP 连接，日志进程和主界面同时连着会互相挤，短连接就是为这个。
