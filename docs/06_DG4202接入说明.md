# DG4202 接入说明

> 对象：RIGOL DG4202（双通道 200 MHz 任意波形发生器，S/N `DG4E202401525`，固件 `00.01.14`）
> 代码：`host/dg4202.py`（驱动本体）、`host/lsa_src.py`（`Dg4202(Source)` 适配层）
> 本文所有命令与返回值均为**真机实测**，不是手册抄录；与手册冲突处以实测为准并注明。

---

## 0. 一句话结论

DG4202 在本项目里**不走 VISA、不走串口**：Windows 上走 WinUSB + pyusb，树莓派上走内核 `usbtmc` 暴露的 `/dev/usbtmc0`。
谐波合成优先用仪器**内置谐波模式**（`APPL:HARM` + `HARM:USER` 掩码），超出 16 次或带非整数倍干扰时改用 **ARB 波形上传**（`DATA:DAC`，注意是偏移二进制）。

---

## 1. 传输层：为什么不用 pyvisa

### 1.1 本机 VISA 是坏的（实测证据）

| 检查项 | 结果 |
|---|---|
| `ctypes.WinDLL("visa32.dll").viOpenDefaultRM()` | `-1073807202` = `0xBFFF009E` = `VI_ERROR_LIBRARY_NFOUND`（"A code library required by VISA could not be located or loaded."） |
| `ctypes.WinDLL("nivisa64.dll")` | `OSError [WinError 1114] 动态链接库(DLL)初始化例程失败` |
| 32 位 `C:\Windows\SysWOW64\...\powershell.exe` + P/Invoke visa32 | `Unable to load DLL 'visa32.dll' ... 0x8007045A` |
| 注册表 `HKLM:\SOFTWARE\VISA` | 不存在（只有 `HKLM:\SOFTWARE\National Instruments\NI-VISA`） |
| `C:\Program Files\IVI Foundation\VISA\Win64\Bin` | 空目录（只有插件 DLL，没有主库） |

结论：**64 位主库缺失、32 位主库 DllMain 失败**，两条路都断。因此 `pyvisa` 以及依赖它的第三方库（`rigol-dg4162-control`、`Rigol_Generator_GUI`）在本机都不可用。我们只借鉴它们的 SCPI 方言，不引入依赖。

### 1.2 Windows：WinUSB + pyusb

设备被 RIGOL 默认的 `usbtmc.sys` 认领时，libusb 看不到它。处理办法二选一：

- 用 **Zadig** 把 `VID_1AB1&PID_0641` 的驱动换成 **WinUSB**（本项目采用这条）；
- 或仍走 `usbtmc.sys` 的用户态句柄（实测：`CreateFile`/`WriteFile` 成功，**`ReadFile` 永久阻塞**，不可用）。

装好 WinUSB 后：

```python
import usb.core, usb.backend.libusb1 as bl, libusb_package
backend = bl.get_backend(find_library=libusb_package.find_library)   # 关键：默认 get_backend() 返回 None
dev = usb.core.find(idVendor=0x1AB1, idProduct=0x0641, backend=backend)
```

端点（接口 0，`class=0xFE/subclass=0x03/protocol=0x01`）：

| 端点 | 方向 | 类型 | wMaxPacketSize |
|---|---|---|---|
| `0x02` | OUT | bulk | 512 |
| `0x86` | IN | bulk | 512 |
| `0x88` | IN | interrupt | 64（STB，不是数据口） |

选端口规则：先 `(ep.bmAttributes & 0x3) == 2` 过滤 bulk，再按 `bEndpointAddress & 0x80` 分 IN/OUT。
USBTMC 报文头 12 字节，`bTag` 递增回绕，响应头 `msgid/n/eom` 必须校验后再读正文。

### 1.3 树莓派：`/dev/usbtmc0`（推荐）

树莓派内核自带 `usbtmc` 模块，DG4202 插上即出现 `/dev/usbtmc0`，**不需要 pyusb、不需要 detach 驱动**：

```bash
printf '*IDN?\n' > /dev/usbtmc0
cat /dev/usbtmc0        # Rigol Technologies,DG4202,DG4E202401525,00.01.14
```

默认权限是 `crw------- root root`，装一条 udev 规则即可让普通用户读写：

```bash
# /etc/udev/rules.d/99-rigol-usbtmc.rules
SUBSYSTEM=="usbmisc", ATTRS{idVendor}=="1ab1", MODE="0666", GROUP="plugdev"
```

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=usbmisc
```

> **坑（很费时间的一条）**：内核 usbtmc 的 `poll()` **只在驱动缓冲区里已有数据时才报 POLLIN，它不会替你发起 bulk IN**。
> 所以「先 `select()` 等可读再 `read()`」会永远等不到（实测 select 3 s 恒为 False，而紧接着的阻塞 `read()` 2.5 ms 就拿到 49 字节 IDN）。
> 正确写法是**直接阻塞 `read()`**（驱动内部约 5 s 超时，没应答抛 `EIO`），只在补收残片/清管道时才临时切 `O_NONBLOCK` + `select`。

### 1.4 传输层自动选择

`dg4202.open_transport(serial=None, timeout_ms=3000)`：

- POSIX 且存在 `/dev/usbtmc*` → `UsbtmcDev`（内核驱动文件 IO），并逐个读 `*IDN?` 校验序列号；
- 否则 → `Usbtmc`（pyusb + WinUSB）。

### 1.5 USB 假死与恢复

对**写-only 节点**发查询（见 §3.1）会让读操作等满超时，之后内核 usbtmc 可能楔住（后续读返回 0 字节）。恢复办法是重枚举 USB 设备：

```bash
# 找 idVendor=1ab1 的 usb 设备，对 authorized 写 0/1
for d in /sys/bus/usb/devices/*; do
  [ "$(cat $d/idVendor 2>/dev/null)" = "1ab1" ] || continue
  echo 0 | sudo tee $d/authorized >/dev/null; sleep 1
  echo 1 | sudo tee $d/authorized >/dev/null
done
```

驱动里对应的软件保护：`Scpi.resync()`（`*CLS` + 清输入缓冲 + 抽空错误队列）、`q()` 的空帧计数（上限 16 次，超限标记失步）。

## 2. 一次通信的基本形状

```python
import dg4202
s = dg4202.Scpi()            # 自动选择传输层；默认按 SERIAL_DEFAULT="DG4E202401525" 找设备
s.identify()                 # → "Rigol Technologies,DG4202,DG4E202401525,00.01.14"
s.resync()                   # 建议每次接管仪器先抽空错误队列，返回丢弃条数
```

`q(cmd)` 返回多行应答，`one(cmd)` 取第一行，`w(cmd, settle=…)` 写命令。
**同类设备上出现过的"回复错位"问题**（某次查询只回了终止符空帧，后续读把 `VPP` 这类单位 token 喂给数值查询）在本驱动里由空帧计数 + 失步保护兜住。

## 3. SCPI 方言（固件 00.01.14 实测）

### 3.1 写-only / 未定义节点（查询必卡满超时，不要碰）

| 节点 | 现象 |
|---|---|
| `:TRIGger<n>:SOURce?` | 超时 |
| `:HARMonic:STATe?` | `-113,"Undefined header"` |
| `:HARMonic:COUNt?` | 超时 |
| `:FUNCtion:ARBitrary:SRATe?` | 写是接受，**查询 3 s 无应答** |
| `:OUTPut<n>:FILTer?` | 超时 |
| `:HARMonic:USER?` | 超时（掩码只能记在进程里） |
| `:HARMonic:AMPLitude? 17` | 超时（越界查询会卡 5 s） |

### 3.2 常用节点与实测行为

| 命令 | 实测 |
|---|---|
| `:SYSTem:ERRor?` | 干净时精确返回 `0,"No error"` |
| `:SOURce<n>:FUNCtion SIN\|SQUare\|RAMP\|PULSe\|NOISe` | 回读短名 `SIN/SQU/RAMP/PULSE/NOISE`；**`TRIANGLE` 会被静默当成 `RAMP`**（DG 没有独立三角波） |
| `:SOURce<n>:FUNCtion:RAMP:SYMMetry 50` | 三角波必须走这个节点（带 `FUNC:`）；写 `:SOUR1:RAMP:SYMM` → `-113` |
| `:SOURce<n>:VOLTage` | 值随当前单位；写 `:VOLT 2VPP` 接受但**只换算不改单位** |
| `:SOURce<n>:VOLTage:UNIT?` | `VPP` / `VRMS`；可能回空 → 兜底用 `:VOLT:HIGH?` − `:VOLT:LOW?` 算 Vpp |
| `:SOURce<n>:VOLTage:OFFSet?` | `-113`（长名不行）；短名 `:VOLT:OFFS?` 有效 |
| `:OUTPut<n>` | 必须 `ON` / `OFF` |
| `:OUTPut<n>:LOAD` | 默认 `50`（Ω）。**本项目一律显式写 50**：同一配置下 `LOAD 50` 得 h1 峰值 200.42 mV / h3 50.27 mV，`LOAD INFINITY` 就**正好折半** |
| `:SYSTem:REMote` / `:LOCal` | 均 `-113`，**DG 不需要先进远程**；驱动里是 no-op |
| `:FREQuency:STARt?` / `:STOP?` | 扫频起止用这两个；`:SWE:STAR?` 未定义 |
| `:SWEep:TRIGger:SOURce` | 枚举是 `INTernal / EXTernal / MANual`，**没有 IMM**（写 IMM → `-220`），回读 `INT/EXT/MAN` |
| `:TRIGger<n>` | `-113`（手动触发不是这个助记符） |

错误码原文（用于识别）：

```
-410,"Query INTERRUPTED"        -113,"Undefined header; keyword cannot be found"
-220,"Parameter error"          -350,"Queue overflow"
```

## 4. 谐波模式（本项目的核心用法）

### 4.1 进模式与三条命令

```
:SOURce<n>:APPLy:HARMonic [<freq>[,<amp>[,<offset>[,<phase>]]]]   # 进入谐波模式（带参数时顺带设定）
:SOURce<n>:HARMonic:ORDEr <2..16>                                # 有效阶次上限
:SOURce<n>:HARMonic:TYPe EVEN|ODD|ALL|USER                       # 默认 EVEN
:SOURce<n>:HARMonic:AMPLitude <sn>,<Vpp>   sn=2..16               # ★ 单位是绝对 Vpp
:SOURce<n>:HARMonic:PHASe <sn>,<deg>       sn=2..16               # 0..360
:SOURce<n>:HARMonic:USER <X…>                                    # ★ 总开关（16 位掩码）
```

### 4.2 掩码 `HARMonic:USER` —— 最容易漏的一步

格式是 **一个 `X` + 15 位二进制**，最左的 `X` 是基波（固定），后面 15 位依次对应 **2…16 次**谐波，`1=输出`、`0=不输出`：

| 掩码 | 含义 |
|---|---|
| `X000000000000000` | 全关（**出厂默认就是它**） |
| `X010000000000000` | 只出 3 次 |
| `X011000000000000` | 只出 3 次 + 4 次 |

驱动里的 `dg4202.harm_mask(orders)` 负责拼这个串，常量 `HARM_MASK_OFF = "X000000000000000"`。

> 这一步没做，就会出现"**`HARM:AMPL` 写得进、读得回、错误队列还干净，但输出上一点谐波都没有**"——本项目在这个坑上耗了十几轮实验才定位。

### 4.3 其它三个坑

1. **未写过的阶次默认不是 0**：`HARM:AMPL? k` 出厂回 `1.264722E+00` Vpp（2…16 阶全是这个值），只写要用的阶会让其它阶一起输出。所以 `set_harmonics()` 默认 `zero_unused=True`，把不用的阶显式写 0（实测写 0 生效，回读 `0.000000E+00`）。
2. **相位默认不是 0**：未指定时 h3 回读 0、h4 回读 `9.000001E+01`（90°）。
3. **上限 16**：`HARM:AMPL 17,x` → `-220,"Parameter error"`；直接写 `HARM:ORDER 40` 会**静默钳到 16**（写 17 时先冒一条 `-410`）。

### 4.4 相位只被部分执行

实测固定幅度（基波 0.20、h3 0.12、h4 0.08 Vpp）只改 `HARM:PHAS`：

| 相位设置 | 理论 Upp | 实测 Upp |
|---|---|---|
| `(h3,h4) = (0,0)` | 289.32 mV | **291.81 mV（+2.49）** |
| `(h3,h4) = (180,0)` | 352.54 mV | 322.22 mV（−30.33） |

也就是说：写 180° 输出确实变了（+30.4 mV），但没到理论的 +63.2 mV。
**结论：全零相位可靠；需要精确非零相位时一律转 ARB。**

### 4.5 正确的命令顺序（`set_harmonics` 的实现）

```
FUNC SIN → VOLT:UNIT VPP → OUTP:LOAD 50 → HARM:TYPE USER → HARM:ORDER <最大阶>
→ 未用阶 AMPL k,0 / PHAS k,0 → APPL:HARM → FREQ → VOLT → VOLT:OFFS 0
→ 各阶 AMPL k,<Vpp> / PHAS k,<deg> → ★ 最后写 HARM:USER <掩码> → 等 3 s
```

- 最后一步写完**要等约 2.5–4 s** 波形才重建完（期间读到 0 mV 是正常的）。
- 命令会被偶发吞掉，所以驱动末尾有**读回核对**：逐阶比对 `HARM:AMPL? k`（容差 1e-6）与 `HARM:PHAS? k`（容差 0.05°），不一致就整表 + 掩码补写一次。
- `set_harmonics()` **只配波形、不开输出**，调用方要显式 `output(True)`。

## 5. ARB 波形上传

### 5.1 数据格式：偏移二进制，不是有符号码

```
[:TRACe]:DATA:DAC VOLATILE,<value>,<value>,...
```

十进制 `<value>` 范围 **0000~3FFF（0..16383）**，**8192 才是零电平**。
驱动常量：`ARB_CODE_MID=8192`、`ARB_CODE_MAX=16383`、`ARB_FULL_SCALE=8191`（相对零电平的最大偏移）。

> **本项目踩到的最深的坑**：一开始按有符号码发 `-8191..+8191`，负半周被当成 8192 以上的高码值，输出变成**全波整流**。
> 症状极具误导性：峰峰值只剩一半、`h2/h1 = 0.42`、`h4/h1 = 0.085`（与全波整流理论值完全吻合），
> 而**内置正弦 `SIN` 模式完全正常**——所以最初一直怀疑模拟前端和测量链，实际是上传数据本身错了。

### 5.2 限制

| 项 | 值 |
|---|---|
| 点数 | 2 … **16384** |
| 归一化 | 先除峰值再乘 8191，再加 8192，最后夹到 `[0, 16383]` |
| 采样率 | `srate = freq × n ≤ 500 MSa/s`；频率要**向下取整**后再算，避免 120.0005 MHz 这类越界 |
| 幅度 | USER/ARB 模式下 `:VOLT <A>` 就是 **Vpp = A** |

写入序列（`load_arb`）：

```
FUNC SIN（先离开 USER，否则 FREQ 被复位）
→ DATA:DAC VOLATILE,<逗号分隔整数>
→ VOLT:UNIT VPP → FREQ → VOLT → VOLT:OFFS
→ FUNC USER → FUNC:ARB:SRAT <srate>
```

### 5.3 什么时候必须用 ARB

- 需要的相对阶次 > 16；
- 分量不是基波的整数倍（例如赛题的干扰项 `u_j` 是 41×F0 / 35×F0，谐波模式放不出来）；
- 需要精确的非零相位。

## 6. 谐波优先 / 不能则转 ARB 的判定

`lsa_src.Dg4202.load_wave(vals, freq_hz, amp_vpp, ch=1, offset=0.0, tones=None, reason=None)` 返回值 `(mode, note)`，`mode ∈ {"harm","arb"}`：

| 条件 | 走向 | 提示文案 |
|---|---|---|
| `tones is None`（带干扰 / 单音） | ARB | 调用方给的 `reason` |
| 只有基波 | ARB | — |
| 阶次非整数或 < 1 | ARB | — |
| 相对基波不是整数倍 | ARB | — |
| 要求非零相位 | ARB | "谐波模式不支持精确相位" |
| `max(相对阶次) > 16` | ARB | "最高 17 次（基波 1 次）→ 相对基波 17 次，超过 DG4202 谐波上限 16 次" |
| 其余 | **harmonic** | "谐波模式：基波 …Hz/…Vpp + 相对 k 次…" |

能走谐波时的换算（**最容易写错的一行**）：

```python
base_k = min(绝对次数)                 # 例如 tones = ((2,1.0),(6,0.55)) → base_k=2
f_play = freq_hz * base_k              # 播放频率必须是 2×F0，不是 F0
harm   = [(round(m / base_k), Vpp, phase) for ...]
```

配完必须 `self.output(True, ch)` 再返回。

## 8. 测量链路上配套的三个开关

DG4202 输出在 **≈585–600 kHz 有一根固定的约 6 mV 残留**（不随输出幅度变，输出一关就没有，属于仪器内部的固定杂散）。而前端频响补偿 `lsa_eq` 在 550 kHz 处要补 **×7.12**，会把这根残留放大成 60–90 mV 的 Upp 虚高。

因此 `lsa_touch.py` 里 `StepCalib._measure_env()` 在 `self.src.name == "DG4202"` 时给 `_contest_one.py` 子进程注入三个环境变量（AFG 一律不加，行为不变）：

| 变量 | 值 | 作用 |
|---|---|---|
| `LSA_EQ_FHI_HZ` | `520000` | 补偿只做到 520 kHz |
| `LSA_EQ_LP_HZ` | `520000` | 补偿后再加一道硬低通 |
| `LSA_FIT_RESID_MAX` | `0.15` | 拟合残差门限放宽（否则会退回分位数法，Upp 系统性偏高约 10 mV） |

三者都可以单独用环境变量覆盖，默认不改变原有行为。

## 10. 已知限制

1. **谐波阶次上限 16**，第 17 次及以上只能 ARB 合成。
2. **`HARM:PHAS` 只部分执行**，精确相位只能靠 ARB。
3. **ARB 点数上限 16384**、采样率上限 500 MSa/s，高频点要用少点数。
4. **`:FUNC:ARB:SRAT` 查询无应答**，采样率只能记账不能回读。
5. **USB 偶发假死**，需要重枚举（§1.5）；树莓派上建议把重枚举做成开机自检的一步。
6. 三角波是通过 `RAMP` + `SYMM 50` 实现的，不是独立波形。
7. 输出负载默认 50 Ω；改 `LOAD INFINITY` 幅度会翻倍，本项目固定 50 Ω。

## 11. 常见故障对照表

| 现象 | 先查 |
|---|---|
| 谐波完全没有输出 | `HARM:USER` 掩码是不是还是 `X000000000000000` |
| 谐波有输出但比例不对 | 其它阶次没清零（默认 1.2647 Vpp） |
| ARB 峰峰值只有一半、h2 很大 | 上传数据是不是用了有符号码而不是 `0..16383` |
| 幅度整体偏大/偏小一倍 | `:OUTP:LOAD` 是 50 还是 INFINITY |
| 查询超时、之后全部错位 | 是不是查了写-only 节点；先 `resync()`，不行就重枚举 USB |
| `--idn` 超时但 `lsusb` 看得到 | `/dev/usbtmc0` 权限；或 USB 假死 |
| 读到 0 字节后一切失败 | USB 假死，按 §1.5 重枚举 |
