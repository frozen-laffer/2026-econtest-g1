## 1. 任务目标与边界

### 1.1 目标（可验收）

| 编号 | 目标 | 验收指标 |
|---|---|---|
| G1 | 稳定接收三通道差分采样流 | 连续 10 分钟丢包率 < 1e-5 |
| G2 | 实时时域波形显示 | 刷新率 ≥ 20 fps，无可见卡顿 |
| G3 | 实时频谱显示 | 频率分辨率 ≤ 100 Hz，峰值定位误差 < 0.1% |
| G4 | 基本测量 | 幅度误差 < 2%，频率误差 < 0.1% |
| G5 | 谐波/失真分析 | 可给出 H1~H5、THD、SNR、SINAD、ENOB |
| G6 | 反向控制 | 可改采样率/增益/耦合/触发，1 s 内生效 |
| G7 | 标定与自检 | 支持两档增益的直流标定，系数持久化 |

### 1.2 明确不做（边界）

- ❌ **不做 ARM/嵌入式侧开发**（那是 STM32 任务书的范围）
- ❌ **不做新协议的定义**（协议由 STM32 侧 P0-7 主导，本任务书只**提出需求并兼容**）
- ❌ **不依赖板上 3.5" TFT**（屏挂在 STM32 上且刷新为秒级，见评估文档 §4.1）
- ❌ 不做量化/机器学习（本题不涉及）

### 1.3 关键约束（来自硬件事实）

| 约束 | 值 | 来源 |
|---|---|---|
| ADC 位数 | 12-bit 差分，满量程 **±2047**（二进制补码） | 评估文档 §2.3 |
| 参考电压 | **3.000 V**（MAX6071） | 基线 §6 |
| INA 可切增益 | **×2.00 / ×20.16** | 基线 §4.1 |
| FDA 增益 | **≈ ×1.96**（Rf=2.49k / Rg=1.27k） | 基线 §4.1 |
| 通道数 | 3（差分） | 基线 §2 |
| 可寻址采样率（固件现状） | TIM8 ARR=849 → **200 kSPS**；改造后 1 k~3 MSPS | 评估文档 P0-5 |
| 链路 | 100 Mbit 以太网（W5500），实测约 10 Mbps | 基线 §9 |
| 板上共模偏置 | SIG_VCM ≈ VREF/2 = **1.5 V** | 基线 §6 |

> **电压换算总公式**（本任务书所有幅度计算的唯一依据）：
> ```
> V_in[uV] = (raw + offset_code) × 3_000_000 / 2047 / (G_ina × 1.96)
> ```
> 其中 `raw` 为 ADC 差分码（−2047..+2047），`offset_code` 为零点校正量（有符号），
> `G_ina ∈ {2.00, 20.16}` 由当前增益档决定。
> **精确系数必须经 §7 标定后写入配置，不得使用上面的标称值直接计量。**

## 2. 硬件接口与网络拓扑

```
┌──────────────┐  100M 以太网   ┌──────────────────┐
│ STM32G474    │◄──────────────►│ Raspberry Pi 4B  │
│ + W5500      │  直连(不接交换机) │ + HDMI 显示器     │
│ IP 192.168.1.200                │ IP 192.168.1.110 │
└──────────────┘                └──────────────────┘
       │                                  │
   RF1/RF2/RF3 (SMA)                 键盘/鼠标（可选）
   被测信号输入
```

| 项 | 值 | 备注 |
|---|---|---|
| STM32 IP | `192.168.1.200` | `main.c:141` 硬编码，**需与固件 P1-8 一起集中化** |
| 树莓派 IP | `192.168.1.110` | `main.c:147` 硬编码为 UDP 目标 |
| 子网掩码 | `255.255.255.0` | |
| **高速数据流** | **UDP，目的端口 8080**（STM32 → 树莓派） | `W5500_HighSpeed_UDP_Init(5001, 192.168.1.110, 8080)` |
| **控制通道** | **TCP，STM32 监听 5000**（树莓派 → STM32） | `W5500_TCP_Server_Init(5000)` |
| 调试串口 | 不经树莓派 | USART1 115200，PC4/PC5 |

> ⚠️ **端口不一致的历史负担**：`w5500_network.c:550` 定义 `HS_UDP_PORT 6000`，
> 而 `main.c:150` 传的是 `8080`。初始化时以 `main.c` 的实参为准（8080），
> 但 socket 重建时（`w5500_network.c:696`）会用 `HS_UDP_PORT`（6000）→ **可能失效**。
> 这是固件 P0-7 要一并修的 bug，树莓派侧暂时**两个端口都监听**以防万一。

### 2.1 网络调优（必须在树莓派侧设置）

```bash
# 1) 加大 UDP 接收缓冲，防止突发丢包
sudo sysctl -w net.core.rmem_max=16777216
sudo sysctl -w net.core.rmem_default=4194304

# 2) 关掉反向路径过滤（直连场景）
sudo sysctl -w net.ipv4.conf.all.rp_filter=0

# 3) 建议设静态 IP（避免 DHCP 抖动）
# /etc/dhcpcd.conf 或 NetworkManager 里固定 192.168.1.110/24
```

Python 侧socket 也要设：

```python
sock.setsockopt(socket.SOL_SOCKET, socket.SO_RCVBUF, 8 * 1024 * 1024)
```

## 3. 接口协议规范

### 3.1 高速数据流（UDP，STM32 → 树莓派）

#### 3.1.1 目标格式（本文档提出，待 STM32 侧 P0-7 实现）

```
偏移  长度  字段          类型      说明
0     4     magic         uint32    0x4C534D54 ('LSMT' = Lab Scope Measurement Trace)
4     4     sample_idx    uint32    本包首个样本在全流中的绝对序号（★关键★ 用于拼帧与丢包检测）
8     4     seq           uint32    包序号，每包 +1，回绕用于快速校验
12    2     fs_khz        uint16    当前采样率（kHz），如 200
14    1     ch_mask       uint8     bit0..2 = CH1..CH3 有效
15    1     gain_code     uint8     增益档：0=×2.00, 1=×20.16, 其他=预留
16    1     flags         uint8     bit0=AC耦合, bit1=触发点在本包, bit2=单次采集
17    1     reserved      uint8     对齐用
18    2     samples       uint16    **本包每通道样本数**
20    2     crc16         uint16    对 offset 4..19 的 CRC-16/CCITT
22    N*2*ch  payload     int16[]   通道数据，**交错(interleaved)**：
                                     [s0_ch1, s0_ch2, s0_ch3, s1_ch1, ...]
```
**包头固定 22 字节**。字节序 **小端**（STM32 与树莓派均为小端，无需转换）。

> **为什么必须交错**：便于按样本序号对齐、便于单通道抽取；且与 STM32 三路 ADC
> 同步采样的自然产物一致。

#### 3.1.2 包大小与延迟权衡

| samples/包 | 包头 | 载荷(3ch) | 总长 | 200 kSPS 下包率 | 1 MSPS 下包率 | 适用 |
|---|---|---|---|---|---|---|
| 128 | 22 | 768 B | 790 B | 521 pps | 2604 pps | 低延迟 ✅ **推荐** |
| 256 | 22 | 1536 B | 1558 B | 260 pps | 1302 pps | 平衡 |
| 512 | 22 | 3072 B | 3094 B | 130 pps | 651 pps | 高吞吐 |

**建议默认 `samples = 128`**：单包延迟约 0.64 ms@200 kSPS / 0.128 ms@1 MSPS，
包率与开销都可接受。**由 STM32 侧决定并在 `samples` 字段告知**，树莓派不得假设固定值。

#### 3.1.3 临时兼容模式（STM32 未改协议前）

现有 STM32 发送的是**自制 6 字节包头**（`w5500_network.c:579-588`）：

```
0  2  seq_id Hi/Lo
2  1  flags: [7:6]=half_id, [5:4]=seg_id
3  1  sample_cnt（本包差分样本数，170/172）
4  2  reserved
```
载荷为**每样本 6 字节**（3 通道 × int16），但内容是 `x[n+1]-x[n]` 的**相邻点差**（**错误行为**，见评估文档 P0-3）。

**兼容策略**：`receiver.py` 用 `magic` 字段**自动判别格式**：
- 读到 `0x4C534D54` → 新格式（22 字节头）
- 否则按旧 6 字节头解析，并在 UI 上**显式告警**："旧格式/含错误求差，数据不可用于测量"

> ⚠️ **不要**在旧格式下尝试测幅度或频谱 —— 数据被微分器扭曲了，结果无意义。
> 旧格式只用于**联调链路连通性**。

### 3.2 控制通道（TCP，树莓派 → STM32，端口 5000）

#### 3.2.1 目标命令包（16 字节）

```
偏移  长度  字段          说明
0     1     cmd           命令码，见下表
1     1     ch_mask       bit0..2 = CH1..CH3 使能
2     1     gain_code     0=×2.00, 1=×20.16
3     1     coupling      bit0..2 = CH1..CH3 的 AC(1)/DC(0)
4     4     fs_hz         目标采样率（Hz），**32 位**（★修复原 uint16 截断★）
8     4     trig_level    触发电平（ADC 码，有符号 int32）
12    1     trig_mode     0=AUTO, 1=NORMAL, 2=SINGLE
13    1     flags         bit0=启动/停止, bit1=请求状态回传
14    1     rsv
15    1     checksum      offset 0..14 的累加和低 8 位
```

#### 3.2.2 状态回传包（16 字节，STM32 → 树莓派）

```
0     1     rsp          0x81 固定
1     1     status       0=idle, 1=running, 2=single-done
2     1     ch_mask      当前生效
3     1     gain_code    当前生效
4     4     fs_hz        实际采样率（Hz）
8     4     drop_count   环形缓冲溢出计数（★新增，诊断必需★）
12    2     pkt_rate     当前包率（pps）
14    1     err          0=正常，非0=错误码
15    1     checksum
```

#### 3.2.3 现存缺陷（必须在 STM32 侧修）

| 缺陷 | 位置 | 影响 |
|---|---|---|
| `sample_rate` 是 `uint16_t` | `w5500_network.h:74` | 200000 → **3392**，频率轴错 59 倍 |
| 强制转换丢高位 | `w5500_network.c:384` | 同上 |
| 无 `drop_count` 回传 | — | 无法诊断丢包 |
| 命令包仅 8 字节 | `w5500_network.h:70-78` | 装不下 32 位采样率与触发电平 |

### 4.2 数据流

```
UDP socket
   │  (recvfrom, 线程 A)
   ▼
receiver.py ── 解析包头 / CRC 校验 / 判定新旧格式
   │          统计：收包数、丢包数、乱序数、CRC 错
   ▼
ringbuf.py ── 按 sample_idx 落位（不按到达顺序！）
   │          缺口即标记为"缺失"，绝不插值
   ▼
stream.py ── 取最近 N 点（N 可配置，2^12 ~ 2^16）
   │
   ├──► dsp/measure.py  ──► Vpp / RMS / f / THD …  ──┐
   └──► dsp/spectrum.py ──► 频谱幅度（dBV）  ────────┤
                                                     ▼
                                            ui/*.py（Qt 主线程）
   ▲
   │ TCP
control.py ◄── UI 控件（改采样率/增益/耦合/触发）
```

**多线程原则**：
- **线程 A**：只做 `recvfrom` + 入环形缓冲，**不做任何计算**（避免丢包）
- **线程 B**（或 Qt timer）：做 DSP + 刷新 UI，目标周期 ≤ 30 ms
- 共享数据用**环形缓冲 + 序号**同步，不用锁争用

### 4.3 关键算法约定

#### 4.3.1 拼帧（最重要，决定频谱质量）

```python
# 必须按 sample_idx 连续拼帧，不能"收到就拼"
# 若本包 sample_idx != 期望值 → 缺口
#   - 在环形缓冲中标记 gap
#   - 若缺口落在当前 FFT 窗内 → 丢弃该帧，等下一帧
#   - 绝不插值补点（会生成虚假谱线）
```

#### 4.3.2 加窗与幅度校正

| 窗 | 主瓣宽 | 旁瓣 | 幅度校正(相干增益) | 用途 |
|---|---|---|---|---|
| Rectangular | 最窄 | −13 dB | 1.0 | 相干采样整周期 |
| Hann | 中 | −31 dB | 0.5 | 通用 |
| **Blackman-Harris** | 宽 | **−92 dB** | 0.35875 | ✅ **测谐波/THD 首选** |
| Flat-top | 最宽 | −90 dB | — | ✅ **测幅度最准** |

**约定**：
- 测**幅度**（Vpp/单频幅值）→ 用 **Flat-top** 或对峰值做三点插值
- 测**谐波/THD**（需要低旁瓣）→ 用 **Blackman-Harris**
- 必须做**相干增益补偿**（除以窗的 `sum(w)/N`），否则幅度系统性偏低

#### 4.3.3 频率轴

```python
fs = fs_khz * 1000.0          # 来自包头，不要在本地假设！
N  = fft_len
freq = np.fft.rfftfreq(N, d=1.0/fs)
```

#### 4.3.4 测量算法（务必用整周期或加窗）

| 量 | 算法 | 注意 |
|---|---|---|
| Vpp | `max - min`（去直流后） | 建议用 99.9/0.1 分位抗毛刺 |
| RMS | `sqrt(mean((x-mean(x))^2))` | 必须先去直流 |
| 频率 | FFT 峰值 + **三点抛物线插值** | 只用峰值 bin 误差最大 ±0.5 bin |
| THD | `sqrt(Σ H2..H5²) / H1` | 用 Blackman-Harris 窗 |
| SNR | `H1 / sqrt(Σ 其余 bin² - 谐波)` | 需排除直流与谐波 bin |
| SINAD | `H1 / sqrt(Σ 所有非 H1 分量²)` | |
| ENOB | `(SINAD - 1.76) / 6.02` | 理论值，需注明 |

#### 4.3.5 相位对齐（多通道）

三个 ADC 由**同一 TIM8 TRGO2 触发**，`sample_idx` 相同即同一时刻。
若固件 P0-4 未修好（三路同步标志），会出现通道间**撕裂**：
**在 UI 上显示同步告警**，并提供一个"通道间互相关峰值"诊断显示，便于定位。

## 7. 标定流程（SOP）

> 目的：把标称的 `G_ina × A_fda` 换成**实测值**，并测出零点偏移。
> 依据：[硬件事实基线](附录/硬件事实基线.md) §10 待实测项。

### 7.1 前置条件

- 已确认信号源精度优于 0.05%
- 已确认继电器处于 **DC 耦合**、确认增益档可控
- 采样率设为 200 kSPS（低噪声），取平均 ≥ 1000 点

### 7.2 步骤

| 步 | 操作 | 记录 |
|---|---|---|
| 1 | SMA 输入**短路到地**（或 50 Ω 端接） | 读 `raw0`（两档各一次）→ `offset_code` |
| 2 | 输入 **100.0 mV DC**，增益 **×2.00** 档 | 读 `raw1` → 反推 `G_x2 = raw1×VREF/(2047×0.1)` |
| 3 | 输入 **100.0 mV DC**，增益 **×20.16** 档 | 读 `raw2` → 反推 `G_x20` |
| 4 | 输入 **500.0 mV DC**，×2 档 | 验证线性度 → 计算 R² |
| 5 | 对 CH1/CH2/CH3 重复 1~4 | 每通道独立系数 |
| 6 | 把系数写入 `config.yaml` | 生成标定报告 |

### 7.3 预期结果（用于判断是否异常）

| 项 | 标称 | 允许范围 |
|---|---|---|
| `G_x2`（= 2.00 × 1.96） | 3.92 | 3.6 ~ 4.2 |
| `G_x20`（= 20.16 × 1.96） | 39.5 | 36 ~ 43 |
| ×2 档满量程输入 | ±0.78 V | — |
| ×20 档满量程输入 | ±77 mV | — |
| `offset_code` | 接近 0 | \|offset\| < 50 LSB |

> ⚠️ 若实测 `G` 偏离标称 **超过 10%**，说明 [基线 §10](附录/硬件事实基线.md)
> 的 Rg 译码有误（`0402WGF1271TCE` 与 `RT0402BRD071K27L` 需人工确认），
> **应停下来复核元件，不要强行用错误的标定系数**。

## 8. 验收测试计划

| 编号 | 测试 | 方法 | 通过判据 |

## 9. 已知风险与假设

### 9.1 假设（若假设不成立，需修改本任务书）

| # | 假设 | 不成立时的后果 | 验证方式 |
|---|---|---|---|
| A1 | STM32 会在 P0-7 实现 §3.1 的 22 字节包头 | 只能用临时兼容模式（数据不可用于测量） | 与固件侧对齐 |
| A2 | 端口最终统一为 **8080/UDP + 5000/TCP** | 需改 `config.yaml` 两个端口 | 读 `main.c:150-151` |
| A3 | 三路 ADC 同步（P0-4）会被修复 | 通道间有撕裂，无法做相位差测量 | 看 `stm32g4xx_it.c` 是否改为 3 路 |
| A4 | 采样率可调（P0-5）会实现 | 只能跑 200 kSPS | 看 `tim.c` 是否改为表驱动 |
| A5 | ADC 改真差分（P0-2） | 幅度/线性度全错 | 看 `adc.c` 的 `SingleDiff` |
| A6 | **标称增益 G=2.00/20.16 正确** | 标定系数错，幅度读数错 | 实测标定（§7），偏差>10% 即假设失败 |

### 9.2 技术风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| W5500 突发丢包（无流控） | 高 | 频谱出现缺口 | 序号检测 + 加大 SO_RCVBUF + 降采样率 |
| 实时 FFT 跟不上（树莓派 4B） | 中 | 掉帧 | 降 `fft_len`；或改用 `scipy.fft` 多线程；或用 numpy 而非 pyqtgraph 重绘 |
| Qt + 高频重绘吃满 CPU | 中 | 卡顿 | 用 `pyqtgraph` + `setData` 复用曲线；限制刷新到 30 fps |
| 旧格式数据被误用于测量 | 中 | **错误结论** | UI 强制告警（M1-3），测量功能在旧格式下禁用 |
| 三路不同步导致相位测量错 | 中 | 相位差测量无效 | T-S2 验证；UI 显示同步告警 |
| `git` 仓库有 150 个构建产物 | 低 | 协作噪音 | （STM32 侧 P2-6 处理） |

### 9.3 开放问题（需与硬件/固件侧确认）

1. **题目最终需要几个通道？** 若只要 1 路，M3/M4 的通道选择逻辑可简化
2. **是否需要瀑布图/长时间记录？** 影响缓冲与磁盘策略
3. **显示用 HDMI 大屏还是树莓派小屏？** 影响 `fps_target` 与布局
4. **是否需要导出数据**（CSV/NPY）供赛后写报告？建议加，成本低
